# План оптимизации производительности при большом количестве людей

## Проблема
При большом количестве людей (~71+) на странице лагает скролл и сама страница из-за:
- отсутствия виртуализации списков (все строки монтируются одновременно)
- отсутствия `React.memo` на компонентах строк/карточек (каждый dispatch перерендеривает все строки)
- тройного полного перерендера при каждом перемещении (snapshot → flash → flash-clear)
- множественных немемоизированных `.filter()` вызовов в Overview
- тяжёлых CSS-эффектов (`backdrop-filter: blur` на sticky-элементах, `container-type` на каждой строке)

---

## Шаг 1: React.memo на компонентах строк и карточек (MEDIUM impact, быстрое исправление)

**Файл:** `src/features/roster/components/person-views.tsx`

Обернуть `RosterRow` и `PersonCard` в `React.memo` — это предотвратит перерендеривание строк, данные которых не изменились.

```tsx
// RosterRow — обернуть в React.memo
export const RosterRow = React.memo(function RosterRow({ ... }) {
  // ... существующий код без изменений
});

// PersonCard — обернуть в React.memo  
export const PersonCard = React.memo(function PersonCard({ ... }) {
  // ... существующий код без изменений
});
```

Также обернуть `LocationBadge` и `Avatar` (маленькие, но вызываются на каждой строке):

```tsx
export const Avatar = React.memo(function Avatar({ person }: { person: Person }) { ... });
export const LocationBadge = React.memo(function LocationBadge({ ... }) { ... });
```

## Шаг 2: Мемоизация фильтров в Overview (MEDIUM impact)

**Файл:** `src/features/roster/components/main-content.tsx`

Заменить немемоизированные `.filter()` на `useMemo`:

```tsx
function Overview({ people, platoons, locations, changeLog, onSection }) {
  // Добавить useMemo для производных данных:
  const distribution = useMemo(() => locationsAndCustom(people, locations), [people, locations]);
  const total = people.length;
  const present = useMemo(() => countInRota(people), [people]);
  const technoparkCount = useMemo(() => people.filter(p => p.location === "technopark").length, [people]);

  // Мемоизировать per-platoon подсчёты:
  const platoonRosters = useMemo(() => 
    platoons.map(platoon => ({
      platoon,
      roster: peopleForPlatoon(people, platoon.id),
    })),
    [people, platoons]
  );

  // Мемоизировать per-location подсчёты:
  const locationCounts = useMemo(() =>
    locations.map(loc => ({
      loc,
      count: people.filter(p => p.location === loc.key).length,
    })),
    [people, locations]
  );

  // Мемоизировать активность:
  const now = Date.now();
  const last1h = useMemo(() => changeLog.filter(l => l.ts >= now - 3_600_000).length, [changeLog]);
  const last24h = useMemo(() => changeLog.filter(l => l.ts >= now - 86_400_000).length, [changeLog]);
  // ... остальной код использует мемоизированные значения
}
```

## Шаг 3: Мемоизация peopleForPlatoon в навигации (LOW-MEDIUM impact)

**Файл:** `src/features/roster/RosterApp.tsx`

Мемоизировать данные для навигации в RosterApp, чтобы Sidebar, MobileSectionNav и SectionDrawer не пересчитывали `peopleForPlatoon` при каждом рендере:

```tsx
// В RosterApp.tsx, после существующих useMemo:
const platoonCounts = useMemo(() => {
  const map = new Map<string, number>();
  for (const platoon of state.platoons) {
    map.set(platoon.id, peopleForPlatoon(state.people, platoon.id).length);
  }
  return map;
}, [state.people, state.platoon]);
```

Передать `platoonCounts` в Sidebar, MobileSectionNav и SectionDrawer вместо `people` для подсчёта.

## Шаг 5: CSS-оптимизация — backdrop-filter (MEDIUM impact)

**Файлы:**
- `src/app/styles/shell.css` (строка 38)
- `src/app/styles/responsive.css` (строка 151)

Убрать `backdrop-filter: blur()` с sticky-элементов topbar и mobile-section-nav. Заменить на полностью непрозрачный фон:

```css
/* shell.css — .topbar */
.topbar {
  /* ... */
  backdrop-filter: none; /* убрать blur */
  background: oklch(15% 0.04 286 / 1); /* полностью непрозрачный */
}

/* responsive.css — .mobile-section-nav */
.mobile-section-nav {
  /* ... */
  backdrop-filter: none; /* убрать blur */
  background: oklch(14% 0.04 286 / 1); /* полностью непрозрачный */
}
```

Это уберёт постоянный GPU-композитинг при скролле.

## Шаг 6: CSS-оптимизация — container-type и transitions (LOW-MEDIUM impact)

**Файл:** `src/app/styles/roster.css`

Убрать `container-type: inline-size` с `.roster-row` (строки 8-9). Контейнерные запросы создают 71+ отдельных контекстов containment. Заменить на обычные медиа-запросы или убрать если не критично:

```css
.roster-row {
  /* Убрать container-type и container-name */
  /* container-type: inline-size; */
  /* container-name: roster-row; */
  /* ... */
}
```

Также убрать или упростить `transition` на `.roster-row` — flash-анимация работает через `!important`, transition на background/border не нужна:

```css
.roster-row {
  /* Убрать transition */
  /* transition: background 0.16s ease, border-color 0.16s ease; */
}
```

Аналогично для `.person-card` (строки 234-236).

## Шаг 8: Удалить неиспользуемую библиотеку motion (LOW impact)

**Файл:** `package.json`

Удалить строку `"motion": "^12.42.2"` из dependencies. Библиотека не используется нигде в коде, но увеличивает bundle.

```bash
bun remove motion
```
